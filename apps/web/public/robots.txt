# https://www.postr.sh/robots.txt
# Postr: conference poster maker for researchers.

# ── Default: crawl allowed; indexation controlled by header ─────────
# Nothing is disallowed for general crawlers, on purpose.
#
# Every private route (/s/, /dashboard, /p/, /profile, /admin, /auth,
# /debug) carries `X-Robots-Tag: noindex, nofollow` from vercel.json,
# and that header is the enforcement. A Disallow here would defeat it:
# a blocked crawler never fetches the page, so it never learns the page
# is noindex, and a URL discovered from an external link can still be
# indexed as a bare listing. Allow the crawl, forbid the index.
#
# For /s/ (share links) there is a second reason. Sharing is switched
# off for now (config/features.ts SHARING_ENABLED; /s/ serves the home
# page).
# If it comes back: Slackbot, Twitterbot and LinkedInBot honour
# robots.txt, so disallowing /s/ would stop share-link previews.
#
# These routes are all cheap to crawl: each returns one small static
# HTML page (the prerendered home page, the prerendered sign-in page, or
# the 404 page), so the crawl-budget cost of allowing them is negligible.
# Do not "tidy this up" by adding Disallow lines.
User-agent: *
Allow: /

# PowerPoint. Share links can hold unpublished research, so this group
# is asked to stay off them (robots rules bind only crawlers that follow

# Two notes on why this group looks different from `*` above.
#
# 1. It uses Disallow where `*` does not, and that is deliberate: the
#    goal here is to keep private content out of training corpora and
#    retrieval, not to keep it out of a search index. Disallow is the
#    right tool for exclusion; X-Robots-Tag is the right tool for
#    deindexing. Different objective, different mechanism.
#
# 2. A crawler that matches a specific group ignores the `*` group
#    entirely, so nothing is inherited and every rule has to be
#    restated here. Do not shorten it.
