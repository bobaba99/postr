**Source:** the MVP editor design, `docs/launch/mvp-editor/bounded-designs.md` §5.2 items 1 and 4 (the switch table, starting text), §3.1 rules 5–6, §3.12 · **Owner decisions (2026-10-07, §6):** D3 "hide both" (import and the `.postr` backup), D4 the hide list approved as a whole, D1 charts kept; the in-editor "Check a figure" stays · **Branch:** `feat/mvp-simplify`, off main `21e6671` · **Status:** implemented; reproduced first in Chromium, Firefox and WebKit with a new committed instrument (`apps/web/scripts/simplify-check.mjs`), green after the change in all three; 86 of 86 mutants killed and 3 of 3 browser blind spots guarded; its one review round (a simple feature: the browser, through the user's entry points, on the frozen copy `simplify-frozen-1`) answered: 7 findings (2 LOW, 5 INFO), Preview no longer draws the prompts (R1-01), two editor sentences corrected (R1-06), the rest recorded (section 9); 88 of 88 mutants killed and 4 of 4 browser blind spots guarded after it; the corrections are in the frozen copy `simplify-frozen-2`.

Evidence labels as in `docs/fixes/README.md`: MEASURED (a number from a re-runnable command), TESTED (a test that fails without the change), INSPECTED (read, nothing ran), UNVERIFIED.

## 1. Symptom

A researcher opens "+ New poster". The title reads "Your Poster Title", every text block holds a guidance sentence ("Background and research question. Provide context, …") and the results table holds made-up numbers ("DV 1", "4.2 (0.8)", "< .01"); each must be selected and deleted before typing, and whatever is left reaches the PDF and the PowerPoint file. Insert › Text stores "Enter your text here.", Insert › Heading "Section Title". A block emptied by hand shows nothing at all. Issues names only the default title. Around this, the editor offers some 44 controls the owner decided the MVP does without (D4): rotate, crop, stretch, the grid, Scan image, custom palettes, Copy a design, style presets, heading style, weight / italic / line height, the Edit block font controls and a second text box, strikethrough / indent / highlight / colour, caption position / spacing / Format, table borders and the table's canvas controls, the citation style menu, the guidelines panel, the Staples help, the editor's Duplicate, and import with its `.postr` backup (D3); the tour, the profile and the public pages describe several of them.

## 3. Method

`apps/web/scripts/simplify-check.mjs` (new; `lib/simplifyStart.mjs`, `lib/simplifyHidden.mjs`, `lib/simplifyKit.mjs`), built on `lib/editorHarness.mjs`, `lib/guestBackend.mjs` and `lib/keepWorkKit.mjs` (extended with a `tour` option, so a first visit's tour starts). Every scenario enters as a user does: a signed-in term holder opens `/p/new`, clicks the sidebar's tabs, selects blocks on the canvas, types with the real keyboard, hovers and right-clicks a table, opens Save PDF and Export › PowerPoint, the dashboard, the profile and the first-visit tour; an older poster is a stored row opened at its address. Prompts are read from computed style (`::before`) and from paint (ink pixels in the block's box, `lib/png.mjs`). Re-run from `apps/web`: `node scripts/simplify-check.mjs [--only id]`, `POSTR_BROWSER=firefox|webkit`. The "before" runs used the same harness against a scratch worktree of `21e6671` (`POSTR_REPO`). Claims, information rows and blind spots are in the script's header. Not covered: the browser's own right-click menu (only Postr's is counted), the caret's place beside a prompt, the dashboard thumbnail (Export › Preview poster is read since review round 1: T13), pages other than the editor, the dashboard and the profile (the copy inventory reads those).

Unit tests, entered the same way in jsdom: `poster/__tests__/mvpHidden.test.tsx` (the switches off, as shipped: every hidden control absent, the kept ones present, the hidden controls' values), `mvpShown.test.tsx` (the switches on: the controls come back), `src/__tests__/mvpHiddenPages.test.tsx` (the dashboard, the tour, the profile), `poster/__tests__/startingText.test.tsx` (the editor page opening a new poster, every template from the layout tab, Insert, typing, Issues on new and older posters); the copy inventory (`src/__tests__/copyInventory.test.ts`) gains the record-29 rules on `src/test/copyScan.ts`, which now tracks every hide switch, the enclosing component and the JSX component elements (`copyScan.test.ts`).

## 6. Root cause

- **Starting text** (H1–H4): `templates.ts` (`makeBlocks`: `content: partial.content ?? (type === 'title' ? 'Your Poster Title' : '')`, the guidance sentences and the sample cells in the template data) and `PosterEditor.tsx` `addBlock` (`content: type === 'heading' ? 'Section Title' : …`) store the starting text as the block's text, so it is printed, exported and has to be deleted. `RichTextEditor` passed `data-placeholder`, but nothing drew it; and the browsers' lone `<br>` means a `:empty` rule would not have either. `PosterEditor.tsx`'s Issues checked only the title and "Enter your text here.".
- **The hide list** (H5): the controls had no switch; the existing pattern (`GALLERY_PUBLIC_ENABLED`, `RULERS_ENABLED`, `LATEX_EXPORT_ENABLED`) is what this record follows.
- **Siblings found and handled:** (a) a prompt longer than the text it replaces makes its block taller: the first table prompt ("Type your results, or paste a table from Excel or Word") made the table run into the heading below it on a new 48 × 36 poster (MEASURED, claim T9o observed while building); "Type or paste" does not (T9o clean in three engines), and the 8-size sweep matches the old sample table exactly (T12: 1 of 8, 24 × 36 in, both with the new prompt and with the old cells served as a control mutant, MEASURED). The template text blocks' prompts are the very sentences they replaced, so their heights do not change (INSPECTED). (b) Copy that names a hidden control outside the editor: the landing page (EN, FR), the About page (EN, FR), the crawler copy (`seo/routes.json`, EN, FR), the closed-poster page ("you can import it"), the tour, the layout tab's export hint, the references paste help, Insert's table description, the table tips, the profile's two rows; all found by the copy inventory's new rules and changed (section 7). (c) Instruments that drive hidden controls: `keep-work-check.mjs` E5, D1 and K11 errored (MEASURED) and now skip while their switch is off; the others are listed in section 10. (d) Older posters keep their text: Issues compares with the old strings rather than rewriting anything (T11: no stored block changed, MEASURED).
- **Found by review round 1 (R1-01):** the rule drew a prompt wherever an empty block is drawn, and Export › Preview poster draws the same `BlockFrame`s outside the canvas (`PosterPreviewOverlay.tsx`), so Preview showed every prompt (MEASURED on the reviewed code: 6 drawn, 1858 ink pixels in its first empty text block, Chromium, T13), against §3.1 rule 6 ("on the canvas only"). The rule is now scoped to `#poster-canvas`. The dashboard thumbnail is drawn from `#poster-canvas` with html-to-image (`data/thumbnails.ts`), so it keeps the prompts, a picture of the canvas (INSPECTED here; the reviewer measured them, R1-03).
- **Sibling left open (R1-02):** the editor's own hints in an empty authors, image or references block ("Add authors in sidebar →", "+ Upload figure", "Add references in Refs tab →", `blocks.tsx`) are text, so Save PDF prints them and Preview shows them (MEASURED, T7 `printEditorHints` and T13 `previewEditorHints`: 3 of 3 on `21e6671` and on this tree, Chromium; 0 in the PowerPoint file). The same family as H3 (editor guidance reaching the PDF), but older than this record and outside its brief; Issues already lists each of those blocks. PLAN.md's Later list.
- **Not explained by this:** the 24 × 36 in overlap (older, section 10); the privacy policy's sentences on hidden features (legal pages, outside the inventory).
