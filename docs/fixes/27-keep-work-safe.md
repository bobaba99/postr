## 1. Symptom

Three ways the editor lost or misreported the user's work.

1. **Enter is not saved (OF-01).** Type a word in a text block, press Enter, type another: two lines on screen. Reload, or open the copy the dashboard's Duplicate makes, or Save PDF after a reload, or export to PowerPoint: one line, the two words run together ("ZQAZQB"). Every multi-paragraph section of a poster is typed this way.
2. **A failed save counts as saved (OF-05, plan item 8).** When a save fails (the network drops, the server refuses), the pill turns red once ("Save failed. Recent changes are not saved."), and then nothing: the change is not sent again, even after the network is back, unless the user edits again; a signed-in user who closes the tab is not warned; the sidebar's Duplicate copies the older saved poster without the change.
3. **⌘S makes a version (owner decision D8).** A PowerPoint hand presses ⌘S by reflex. Each press inserts an unnamed version; the database refuses a 31st version of a poster, and Restore, which first saves the current poster as "Before restore", then stops. ⌘S also did not save the pending change any sooner.

## 6. Root cause

Two causes, and a third, separate binding.

**A — typed text is stored in the browser's markup, not the stored dialect (R3; OF-01, H1, H2).** The stored dialect separates lines with `<br>` (the exports split on it; the paste path already turned another application's blocks into `<br>`, `RichTextEditor.tsx` `handlePaste`). Enter does not make a `<br>` in any engine; it makes a `<div>`. The text block's commit (`read`) ran the sanitizer with no separator, which unwraps the `<div>` and puts nothing in its place; the table cell stored its markup unsanitized, so the `<div>` reached the export, whose parser (`export/richText.ts`) reads an unknown tag as text. A third defect sat on the cell's path and would have hidden a correct cell: the PowerPoint writer's `addTable` flattened a cell's paragraphs into one run list (`.flatMap((p) => p.runs)`), joining its lines whatever was stored (MEASURED after the commit fix alone: "Measure ZQEZQF", `<scratch>/fix27/fix1-chromium.log`).

A fourth piece came out of the first version of the fix: the sanitizer's boundary rule owed a separator at every block boundary once anything had been written, also where the line had already ended. After a list the browser draws the next line directly under it (`…</ul><div>ZQL3</div>`), and a stored `<br>` there draws a blank line; the same for a `<br>` already at a line's end (`a<br><div>b</div>`). The paste path had the same rule (a Google Docs list followed by a paragraph), but on main the typing path never reached it, because it had no separator at all. MEASURED on the first version (`<scratch>/fix27/e10-fix.log`, Chromium): E10's gap from the last item to the next line 1.5 while typing, 2.79 after a reload. The rule this led to (section 7) was incomplete: it missed a line ended by a newline typed at its end (Shift+Enter), review round 2's R2-A1, cause E below.

**B — autosave treats "sent" as "done" (R2; OF-05, H3–H6).** `flush` cleared the pending change before the request (`useAutosave.ts` 206-209 on main), so a failure had nothing left to retry, the tab-close handler (which looked for the debounce timer and the pending change) saw nothing unsaved, and `flushNow` resolved as if the write had happened. The same "forget once sent" let a debounce fire a second write while the first was still out; nothing ordered them (S8).

**C — ⌘S was bound to "save a version"** (`saveVersionNow`), whose 20-version cap lives only on the Versions tab's button; the database's cap is 30.

What these do not explain: the posterId-change drop of a pending change (R1, OF-03/OF-04, the in-editor Duplicate's "Open copy"; the hook keeps dropping it: section 10); two tabs on one poster (last write wins, the banner); text colour from the toolbar not saved (OF-02, not tested here); captions, which are single-line `<input>`s (Enter has nothing to do there); and the title and headings, which swallow Enter by design (E7 clean before and after). The first version of this section also called the figure and table *notes* captions: they are not. The note is a `<textarea>`, which takes Enter (review round 1, R1-A1, cause D below).

## 7. Fix

**A — Enter.**
- `poster/sanitizeHtml.ts`: a `keepWhitespace` option (off by default; the paste path still trims pretty-printed markup) and `sanitizeTyped(html, multiline)`: the sanitizer with `'<br>'` as the block separator (`' '` in a single-line block) and every typed space kept.
