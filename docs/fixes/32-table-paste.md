# Record 32 — A paste into a table cell fills the table from that cell; pasted text takes the poster's style

**Source:** the MVP scope's "pasting tables" (PLAN.md, "Handed on by finished fixes": fix 27's round 2 finding N2-F1, measured by `keep-work-check.mjs` H5); the MVP editor design, `docs/launch/mvp-editor/bounded-designs.md` §3.3 table A rows 1 and 2 · **The rule for a table cell:** the lead's default for the case §3.3 left open (PowerPoint's behaviour) · **Branch:** `fix/table-paste`, off main `089b84d` · **Status:** implemented; reproduced first from the user's entry with a new committed instrument (`apps/web/scripts/table-paste-check.mjs`, a real ⌘C and ⌘V) in Chromium, Firefox and WebKit, green after the change in all three and on the production build in Chromium; its one review round (a simple feature: the browser, through the user's entry points, on the frozen copy `tablepaste-frozen-1`) found 3 MEDIUM defects in the first version (Word's own bold dropped, blank lines at the end of a paste read as rows, a line wrapped in the clipboard's HTML source stored as a line break), 2 LOW and 1 INFO; each reproduced first with the committed instrument in the three engines, corrected, and 0 after; the corrector's audit of its own correction found and corrected a regression it caused in Firefox (text copied between blocks lost a Shift+Enter line and a double space) (section 9); 54 of 54 mutants killed; for the lead from the frozen copy `tablepaste-frozen-2`.

Evidence labels as in `docs/fixes/README.md`: MEASURED (a number from a re-runnable command), TESTED (a test that fails without the change), INSPECTED (read, nothing ran), UNVERIFIED.

## 1. Symptom

A researcher has a results table on the poster and pastes one value into a cell: the whole table is replaced by a one-cell table holding that value. Pasting a range copied from Excel into the second row replaces the table with the range, so the header row above it is gone and the range sits at the top. Pasting text from a web page into a text block keeps the page's red text and yellow highlight; pasting from Google Sheets puts the sheet's style sheet into the block as words ("td {border: 1px solid #cccccc;} …"), and a paragraph from Google Docs comes in bold. And a cell's text that looks like markup becomes markup: a cell reading `<img src=x onerror=…>` in the copied table runs its script in the editor.

## 6. Root cause

- **The table (H1, H2, H3).** One handler for the whole table, `onPasteCapture` on the table block's wrapper (`blocks.tsx`, main `:905`), with no knowledge of the focused cell, called `parseTablePaste` (`tableOps.ts`, main `:135-166`), which returned a fresh `TableData` (column widths and the border preset reset) from any paste with text, and the handler committed it in place of the table. The reader took `textContent` of HTML cells (tags and `<br>` lost, words glued, `&lt;` decoded into a live `<`), split plain text at `\n` only and dropped every blank line, and ignored `colspan`/`rowspan`. The cell draws its stored value as HTML (`TableCellEditor.tsx` `asIs`, kept since fix 12 so a legacy cell keeps its look), so decoded text became markup.
- **Text (H4, H5, H6).** `RichTextEditor.tsx` `handlePaste` cleaned a paste with `sanitizeHtml` alone, whose allow-list is built for the editor's own commands (`execCommand('foreColor')` and `('hiliteColor')` write `<span style="color/background-color">`, so the sanitizer keeps them), not for another application's markup; and it unwraps any element it does not allow, so `<style>`'s CSS became text and Docs' non-bold `<b>` stayed `<b>`.
- **Shared cause.** Both readers took the clipboard's markup without reading what it means: the cell reader as text (decoding markup), the text reader as editor markup (keeping the source's colours and style sheet). One cleaning function (`pasteClean.ts`) now serves both: a text block's paste, a cell's one line, and every cell of a pasted HTML table.
- **Siblings looked for.** The two editable surfaces in the editor are `RichTextEditor` (text blocks, the title, headings, the hidden Content box) and `TableCellEditor`; both now paste through `pasteClean.ts` (INSPECTED: `grep contentEditable src`). The sidebar's fields are `<input>`/`<textarea>`, which take plain text (unchanged, out of scope). Fix 27's Later item R2-A6 (paste fidelity) named Docs' wrapper: fixed here; its other two parts (an `&nbsp;`-only paragraph, newlines between list items) are older; the first is unchanged, the second gone since the review round (section 10). The table note's raw HTML (record 27, R1-A8) is a textarea, not a paste path here.
- **The review round's three defects (section 9).** R1-F1: the not-bold check read a style attribute by pattern, unanchored, so Word's `mso-bidi-font-weight:normal` read as `font-weight: normal`; a style property is now read by its whole name, last declaration first (`styleValue`), which the new white-space reader shares. R1-F2: the plain-text reader dropped one final line break, not all (Chromium's copy of a whole paragraph ends in two), and rule 1 kept the HTML's final `<br>` (WebKit's interchange newline). R1-F3: only the grid path read the source's whitespace as HTML draws it; the text path (rule 1, text blocks, the title) kept a wrapped source line as a newline. R1-F3 and R1-F2's WebKit half share one cause, the text path taking the clipboard HTML's breaks and whitespace as the poster's lines (the grid path had stopped, H3); R1-F2's Chromium half is the plain-text reader's; R1-F1 is unrelated to both. The audit's regression (section 9) was the correction of R1-F3 itself: it read every paste's whitespace as drawn, and Firefox's copy of a field's own text carries no style to say its whitespace is meant.
- **What it does not explain.** The drag-selected range's engine differences (section 10, I-drag-range): the paste event's target is the engine's choice. A stored cell drawn as HTML (`asIs`) remains for values stored before this fix (section 10).

## 7. The change

**The rule table** (`apps/web/src/poster/tablePaste.ts`, its header; the lead's rules 1–3):

| The caret is in | The clipboard holds | Then |
|---|---|---|
| a table cell | HTML with a `<table>` and no other text (Excel, Word, Google Sheets) | a grid: the table's cells |
| a table cell | plain text with a tab or a line break (blank lines at its end aside) | a grid: a row per line, a cell per tab |
| a table cell | any other text | into the cell at the caret, cleaned as a text block's paste is, with no line break at its end |
| a table cell | no text (an image alone) | the browser's own paste, as before |
| a text block, the title, a heading | anything with text | the poster's style wins: bold, italic, underline, strikethrough, sub, sup, lists, line breaks kept; colour, highlight, font, size dropped (on paste only); the source's whitespace read as it draws it |

A grid fills the table from the focused cell, left to right and down; the table grows by rows and columns to hold it; no cell outside the pasted area changes; nothing is dropped. One undo step (fix 12's history: a patch to several cells is a step of its own; one to one cell is marked by the paste event, `stores/inputHint.ts` `notePaste`).

**The shape of each case, and why.**
- **A merged cell** writes its text in its first cell and empty text in the cells it covers, so every cell after it keeps its column (an occupancy grid; a `rowspan` past its table's last row, or 0, stops at the last row, so a merge never grows the paste).
- **Text outside the table** (a paragraph copied with it, a `<caption>`): the plain text holds it too, so the paste is read from the plain text instead of dropping it. A style sheet, script or title is not such text.
- **Each HTML cell** is cleaned like a text block's paste (bold, italic, underline, sub, sup and line breaks kept; colour, highlight, font, size dropped), with source-code whitespace read as HTML draws it (a run is one space; none at a line's start or end; `<pre>` kept), and stored as text ("<" as "&lt;"). **Plain-text cells** are escaped.
- **Column widths** are kept unless columns are added (then even, as Format › Columns does); the border preset and custom borders are kept (the old reader reset both).
- **Blank lines at the end** are not rows, in any spelling (`\n`, `\r\n`, `\r`; one before the review round, all since, R1-F2); an empty line inside is an empty row, and so is one at the start (a single-column range whose first cell is empty keeps its place). Rule 1's one line ends with no `<br>` or newline (an engine's copy of a whole paragraph ends its HTML with `<br class="Apple-interchange-newline">`).
- **The text path** (`apps/web/src/poster/pasteClean.ts`): `parsePasted` parses the clipboard's HTML as the document it is, removes `style`, `script`, `template`, `title`, `head`, `meta`, `link` with their text, and reads the source's whitespace as HTML draws it (since the review round, R1-F3: a run is one space and none is kept at a line's start or end, beside a block's edge or a `<br>`; text under a `<pre>`, or under the nearest element whose style declares `white-space` other than normal or nowrap, as Google Docs' pre-wrap spans, is kept as written; and nothing is collapsed when the clipboard's plain text shows the HTML's text with its spaces and line breaks as written, a `<br>`, a block's edge or a tab between cells counting as a line end and blank lines aside: an engine's copy of text drawn pre-wrap, as Firefox's copy of a field's own text, whose HTML is the bare text); `cleanPastedContent` unwraps a `<b>`/`<strong>` whose own style says it is not bold (normal, lighter, 100–500; the property read by its whole name, the last declaration, `!important` aside: `styleValue`, R1-F1), unwraps `<mark>`, removes every `style` attribute, then the sanitizer as before (a `<br>` where a paragraph ended, or a space in a one-line field). The grid path parses once with `parsePasted` (the cells' ancestors in place, so a table's own white-space style reaches its cells) and cleans each cell with `cleanPastedContent`. Plain text is escaped.

**Files.** `apps/web/src/poster/tablePaste.ts` (new: `readCellPaste`, `pasteGrid`); `apps/web/src/poster/pasteClean.ts` (new: `cleanPastedHtml`, `pastedHtml`, `escapeText`; since the review round also `parsePasted` and `cleanPastedContent`, which the grid path uses); `TableCellEditor.tsx` (its own `onPaste`, and the `onPasteGrid` prop); `blocks.tsx` (the table-wide `onPasteCapture` and its `onPaste` removed; each cell given `onPasteGrid={(rows) => commit(pasteGrid(data, r, c, rows))}`); `tableOps.ts` (`parseTablePaste` removed); `RichTextEditor.tsx` (its paste through `pastedHtml`). The cell's one line is inserted with `execCommand('insertHTML')` and stored by the input event that fires (as typing is; MEASURED by T1 in three engines).

**What users read** (the editor is English only: no French dictionary holds these strings, INSPECTED; the public pages, EN and FR, say nothing about pasting into a table block: INSPECTED, grep; About's "Paste a table or answer three questions in the Figure tab" is the chart ladder's data step, unchanged). The three sentences that described the old paste now say what the code does: the table tips ("📋 Paste cells copied from Word, Excel, or Google Sheets into a cell: they replace the cells from that cell, across and down (a single copied cell replaces that cell's text), and the table grows to fit. Other text with no tabs or line breaks goes in at the cursor."; reworded in the review round, R1-F4: it said such text "goes into the cell itself", yet one copied spreadsheet cell, an HTML table, replaces the cell's text), the Insert tab's "📋 Pasting tables" card ("Copy cells from Word, Excel, or Google Sheets, click a cell of a table block, then paste — the cells fill the table from there, and it adds the rows and columns they need. Each sentence is a claim the instrument measures (T1, G1–G3); that Word, Excel and Sheets put a table on the clipboard is knowledge (UNVERIFIED).

**Bounded:** one rule table of five rows, one cleaning function for every paste (and, since the review round, one style reader and one whitespace reader for every paste). **Out of scope** (section 10): inserting or deleting rows or columns in the middle (Later, the owner), image paste and block copy and paste (the next items), the sidebar fields beyond today's behaviour, a paste over a drag-selected range, comma-separated text, quoted fields in tab-separated text, formatting set by style.
