Auto-Arrange Lab

Postr's proposed Auto-Arrange, as one function. Font sizes never change. Blocks keep their reading order and may move between columns; column widths may change, and text gets taller as its column gets narrower. The layout with the least area past the sheet's bottom edge wins. Sample content, not a real poster.

"Was in" is the column a block sits in before Auto-Arrange (the template's placement).

The function

Fixed: sheet W × H, 1 in margins, 0.6 in gaps, every font size, the reading order b₁…bₙ, and the header across the top. Body height Hb = H − 2 − header − 0.6.

Each block's height at width w: text h(w) from wrapping its words at the fixed font size (narrower → more lines → taller); a figure w ÷ aspect + its caption; a table from wrapping each cell.

Chosen: the cut points that split the reading order into k consecutive columns, and the widths w₁…wk (summing to the body width). Column height Hc = Σ hi(wc) + gaps.

  1. Overflow O = Σ wc · max(0, Hc − Hb), in in², always first.
  2. Evenness U = Σ (Hb − Hc)², spreading the white space.
  3. Stability: blocks moved to another column × "Keep blocks where they were", plus each inch a width moves from equal × "Prefer equal column widths".

F = 1000·O + U + keep·moved + equal·Σ|wc − w̄|

For each candidate set of widths (¼ in steps; ½ in for 4 columns), a dynamic program finds the best cut points exactly. The best F over all candidates wins. Text is measured with Source Sans 3 here; the editor would measure its own fonts.
