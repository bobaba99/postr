`<scratch>` is this session's scratchpad; its run folders are not committed.

## 1. Symptom

A researcher opens the editor's FIGURE tab, picks "Check a figure", pastes a plotting script, presses Check and reads the table. Then they click a text block to fix a caption, or open another tab, and come back: the code box is empty, the language is back to Auto, the table is gone, and the line under the box says "Auto-detect waiting for code…" (FR9's wording). A reload, "Back to My Posters" or another poster loses it too. The same happens to text being typed in the Authors paste box, the References paste box and manual fields, Make a figure's table and its answered steps, the Layout poster name (saved only on Enter or Save) and the version name. On the public plot checker (`/tools/figure-readability`) a reload loses the script, the language and the typed size.

Reproduced on main `b0125c3` by the item 7 reproducer from the user's entry point (a first visitor at `/p/new`, the backend faked at the network with the posters table's row-level security), with the harness committed here, `apps/web/scripts/figure-script-check.mjs` (MEASURED, its version 1; section 4).

## 6. Root cause

**Two parts, and both needed fixing.**

**(1) Loss within one session (L1, L2, and the siblings).** The checker held everything the researcher put into it in its own React state (the script, the language, the checked result, the scan state), and every sibling panel held its typed text the same way. The sidebar destroys a panel on every tab change by two independent mechanisms, each enough alone (MEASURED by the reproducer's interventions): the panel is rendered only while its tab is active (`{tab === 'check' && <FigureTab/>}`), and the panel area is keyed by the tab for its enter animation (`<div key={tab}>`). Selecting a block is a tab change: the selection effect (`Sidebar.tsx:345-367`) sends any newly selected block other than an image or chart to Edit, Authors or References. `FigureTab.tsx`'s header comment already documented this remount; only the Make/Check mode had been lifted out of it, into `PosterEditor`.

**(2) Loss across a reload or another poster (L3, L4, L5, L7).** Nothing stored the script outside memory: no storage key held it in any reading (MEASURED, both reviewers). The page's typed size was memory-only too. Keeping the panel mounted would not have helped: the keep-mounted intervention still lost the reload (1 of 1), and every exit the confirmer found that reloads the editor ("Back to My Posters", and by inspection the update toast's reload, the session-expired modal, the Stripe checkout redirect and the guest's Google conversion) is a full page load.

**Structural sibling, the same shape as fix 02's handed-on L-2:** the editor page keeps `PosterEditor` mounted across a poster change (`Editor.tsx`), so any per-poster draft must follow the poster id while mounted and be written synchronously, or it carries one poster's draft to another (I1, MEASURED) or drops a pending write.

**What this does not explain.**
- The FR8 family (stale results kept rather than lost): image A's scan rows shown while image B is selected (S4a). Items 15 and 17's area; not changed here. The code check's version of it, a table computed for one figure kept next to a pill naming another, was on main too; the fix first made it come back with no click and after every reload, and review round 2 changed it (section 9, R2-01).
- Whether the auto-route should exist at all. It is designed behaviour and out of this item's scope (owner, 2026-10-06).
- The checker's wrong verdicts (items 13–16).
- That the two mechanisms destroy the Authors, References and Make drafts is INSPECTED; the reproducer measured only that they are lost.
- Why a click on the table block's frame above its cells selects nothing (an instrument observation; not investigated).
- Keyboard undo clearing the code box in Playwright's Chromium and WebKit (section 5): a different mechanism, UNVERIFIED in real browsers.

**Checked and not shared:** fix 01's cause (`setPoster` on every sidebar edit) is a different mechanism; so are records 02, 03, 13 and 23 and plan items 5, 6, 8, 12, 19 and 20 (the reproducer's sweep, INSPECTED).

## 7. Fix

**Owner decisions (2026-10-06)**, which set the shape: in the editor the script and its language are kept per poster in this browser (localStorage, `postr.figure-script.<poster id>`, size-capped, written on every change) and survive every exit above; another poster has its own checker, including one opened while the editor stays mounted; on the public page the script, language and typed size survive a reload in sessionStorage and clear when the tab closes; a restored script re-runs its check, so the table comes back; the Figure tab stays on Check once a script has been entered; the same cause is fixed in the sibling panels in memory only, without mounting every tab permanently; account deletion and the storage policy follow.

**A. The checker's draft** (`poster/figureScriptDraft.ts`, new; `ReadabilityPanel.tsx`). The panel no longer owns the script, the language or the check: they are a draft `{ code, lang, checked }`, where `checked` is the inputs of the last Check (`code`, the resolved language, and the width and height it was checked at), read and written through `useScriptDraft(slot)`. The table is computed from those inputs (`runReadabilityCheck`, the old `runCheck` body, pure), so when the panel mounts again or the page reloads the same table comes back, at the size it was checked at — the editor already keeps a result through a later drag of the preview, and this keeps it through a remount the same way. Storage is the record whenever it works: every change is written at once, synchronously (no debounce, so fix 02's L-2 dropped-write mechanism cannot occur); a draft storage cannot take (blocked, full, or a script over 50,000 characters as stored, the script and the version last checked, when it differs, each counted on its own since review round 2) is kept in memory while the page is open (a reload or closing the tab loses it), and its older stored copy is removed so a reload never brings back an outdated script; a box with no code in it stores nothing (blank lines typed first, a language picked before the code, or a table still showing, stay in memory while the page is open; the first version dropped typed blank lines, section 9); only the 10 most recently changed posters keep a script. A stored entry is validated field by field on read. A kept script the parser cannot read shows without a table instead of taking the panel down on every visit. Since review round 2 a Check also records the figure it sized against (`imageId`: the selected image block, or null for the gray figure preview), and in the editor a result for another figure is not shown; a status line says what it is for and when it shows, and a result kept at another size of the same figure says the size it is for (section 9, R2-01).

**B. Per poster while the editor stays mounted** (`Sidebar.tsx:701`). The panel area is keyed by the poster as well as the tab (`${posterId}:${tab}`), so a poster opened in the mounted editor (Duplicate → "Open copy") starts every panel afresh, from its own drafts; nothing of the first poster is written under the second's id (the draft hooks write under the key they read). The sidebar passes the poster to the Figure tab, which gives the checker `posterScriptSlot(posterId)`.

**C. The public page** (`FigureReadability.tsx`). The checker gets the tab's slot (sessionStorage `postr.figure-script-page`) and the typed size is read from and written to sessionStorage (`postr.figure-size-page`). A new tab starts empty at 10 × 7.

**D. Check stays up** (`PosterEditor.tsx`). Before any explicit pick, the Figure tab shows Check when an image is selected or the poster's checker holds a script (`useHasPosterScript`), so a deselect no longer hides a script, and a kept script opens on Check after a reload. An explicit pick still wins (a click on "Make a figure", and Insert › Chart, which picks Make; TESTED since review round 1). A box of blank lines is not a script.

**E. Hygiene.** Account deletion clears every `postr.figure-script.*` entry (`clearStoredFigureScripts`, called from `clearLocalData`); deleting a poster removes its script once the delete has succeeded (`deletePoster`; a failed delete, which the dashboard rolls back, keeps it). The dashboard's Delete and Profile's "Delete all posters" both call `deletePoster` (`Home.tsx:124`, `Profile.tsx:276`: INSPECTED); the dashboard's path is TESTED from its clicks. The Cookies Policy (EN and FR) lists the three new keys under their storage areas, with their lifetimes as the code sets them, and `cookiesStorageInventory.test.ts` pins them to the writer file; Privacy §8 (EN and FR) names the plotting scripts among the notes kept in the browser. The page's promise "your code never leaves the browser" stays true (sessionStorage is in the browser).

**F. The siblings, in memory** (`hooks/useSessionDraft.ts`, new). `useSessionDraft(key, initial)` is `useState` whose value, under a key, lives in a module map for as long as the page is open; writes are synchronous and every mounted reader re-renders, so a write made after the panel unmounted (a parse finishing, a feedback timer) reaches the panel mounted since. With a null key it is plain `useState`, so the components keep their old behaviour outside the editor (the deactivated `/chart-chooser` page, the manuscript panel, unit tests). Kept under the poster id: the Authors paste box, its parse in flight and its feedback (Parse stays disabled on return until the parse lands, so the list cannot be sent twice); the References paste box, manual-entry fields, parse in flight and feedback; the Layout poster-name draft, tied to the name it was typed over (when the poster's name changes some other way — a poster imported over this one — that name shows, as the old sync from the parent did) and ended by Save; the version name; and the Make ladder: its source, answers, step-1 summary, picked-but-unused grouping columns, the variables-form switch, the table being typed, an uploaded workbook's sheet choice, and the variables being listed. The ladder's drafts outlive a tab change, not the step: a used table or sheet clears step 1's drafts, and leaving the variables form resets its rows, as before. Not every tab is mounted permanently (VersionPanel fetches on mount); scan results and the figures chosen in Make's last step are not kept (section 10).

**Why this shape and not another.** Lifting only `code` into `PosterEditor` (TRIAGE's suggestion) would leave the language, the check and the scan behind, carry the script to another poster (I1), and lose the reload (the analogous keep-mounted intervention: L3 1 of 1, MEASURED by the reproducer). Moving only `key={tab}` leaves the conditional render, which alone destroys the state (MEASURED). Mounting every tab permanently would run every panel's mount effects at editor start. Storing the computed result instead of the check's inputs would freeze a verdict the next app version may correct; re-running the inputs is client-side compute (the owner's "cheap"; not timed here). For the restored table's size two readings of "re-runs its check" were possible: at the size it was checked at, or at the preview's current size. The first was taken: it brings back exactly the table that was showing, matching how the editor already keeps a result after a drag; the second would change the table on every tab switch after a drag, and after a reload would score against a preview the researcher did not set (the preview size is not kept across a reload; section 10). Review round 2 found what the first reading left unsaid: the table did not say which size or figure it was for (R2-01, and R1-08 before it); the note now does, and a result for another figure is hidden until that figure is selected again.
