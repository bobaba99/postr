## 1. Symptom

A researcher pastes plotting code into the plot checker (the public page `/tools/figure-readability`, or the editor's Figure tab › "Check a figure") and presses ▶ Check. For code the checker cannot place as R or Python, nothing happens: the button is enabled, nothing on the page changes, and a result already on screen disappears without a word. Pressing R or Python by hand gets a table, but for a plotting system the checker does not read (base R graphics, lattice, plotly, plotnine) that table and its edited code are for ggplot2 or matplotlib, and wrong. Some code is read as the wrong language outright: plotnine as R, an R script carrying a commented-out matplotlib draft as Python.

## 6. Root cause

Two causes, as the reproducer found, plus the confirmer's class inside the second.

**A — the panel has no outcome for "could not decide".** `detectedLang` was `'r' | 'python' | null`, and null meant both "no code" and "could not decide"; `runCheck` handled null exactly as empty code (`setChecked(null); return`), so Check rendered nothing and wiped any result (`ReadabilityPanel.tsx:255-264` on `735636e`, INSPECTED; H1, MEASURED). Nothing announced any outcome: the panel had no live region (MEASURED, SILENT 444 of 444).

**B — language stood in for plotting system, and the scorer read more than the live code.** `detectLanguage` (`readability.ts:2102-2139` on `735636e`) scored the raw text with unanchored patterns and knew only ggplot2 and matplotlib words, and the label, the parser choice and the fix writers all took "R" to mean ggplot2 and "Python" matplotlib. So base graphics, lattice, plotly and pandas scored 0 to 0 (19 of 22 nulls), plotnine scored as R (4 of 4), comments decided D9, and names and strings decided the confirmer's 7 (H2–H5, MEASURED).

The revert (4e9c175) is the link between them: fixing B alone grows A's dead end (22 → 24 nulls stripped, section 4), and fixing A alone (a "pick one" answer) sends unsupported systems to a hand pick that scores them as ggplot2 or matplotlib (on `735636e` 19 of 19 hand picks gave a table, and 12 of those 19 scripts were unsupported systems: base 8, lattice 2, plotly 2; the reproducer: 11 of 16). Hence one batch.

**What this does not explain:** item 16 (the R fix attached to `print(p)` changes nothing; the same fix writers, a different input); item 13 part 2 (the parser's misreads of correctly detected code); the result scrolled out of view at small editor heights (the confirmer: 10–16 px visible in 4 of 10 editor configurations), a second way for Check to look dead that this fix does not touch; the page's print-size change, which hides a result by design (fix 13's era; the owner's answer was about code that cannot be checked; since round 2 of the review the line beside Check says so, section 7).

## 7. Fix

One batch, for the revert's reason (section 6). Two source files.

**B — detection** (`readability.ts`, the end of the file):
- **What is read.** Every pattern runs on `maskCodeForRewrite(code)`: comments and string contents blanked, delimiters kept. This re-lands 9ea9f38's comment stripping and goes further: stripping comments alone changed 0 of the confirmer's 70 verdicts and left words in titles scored (MEASURED by the confirmer). The parsers still read the raw text.
- **The confirmer's class.** An Axes method counts only as its own name (`(?<![\w.$])ax(?:es|s)?…\.`, not inside `max.temp`; `axes.` and `axs[0].` count too); a ggplot scale is `scale_<aesthetic>_<kind>(` (not `scale_factor`, not `autoscale_view`); `<-` counts only as an assignment at the start of a statement (not `y<-0.5`); only a `.savefig(` method counts (Julia has a bare `savefig()`); `import` also matches Python's `from pylab import *` (until round 2 any `import *`, so JavaScript's `import * as d3` read as Python, R2-02). Words in titles are gone with the strings. Round 1 (section 9) found the same class in four more patterns, each anchored where a collision was found: ggplot2's `ggplot(` only as its own name (a wrapper called `myggplot()`), `geom_` only as a called name of its own (geopandas' `.geom_type`, its `.geom_equals()`, a loop variable called `geom_type`), `theme_` only as a call (a variable called `theme_colors`), and matplotlib's system pattern takes `subplots(` only as its own name (plotly's `make_subplots()`). The 13 patterns left as they were (Python's `subplots(` signal, `ggsave(`, `aes(`, `labs(`, `element_*`, `facet_*`, `library(`, `plt.`, `import`, `seaborn`, `figsize=`, `def`/`class`, `set_xlabel`) were each anchored in a scratch run: 0 of 411 outcomes changed (the corpus less its 3 generated scripts, plus the confirmer's 70 snippets; Auto, R picked and Python picked; MEASURED, `scratchpad/fix15-c1/anchors.mts`), so each would be a part no test could fail. `plt.` cannot be anchored usefully: an R variable called `plt.data` looks the same.
- **New signals.** R: `function(`, `TRUE`/`FALSE`/`NULL`, `df$col`, a dotted argument name (`cex.lab =`, which Python cannot write), `main=`/`xlab=`/`ylab=`, a formula, a graphics device (`png(`, `pdf(`…), base graphics functions only R has (`matplot`, `abline`, `curve`, `dev.off`, `par`…; `barplot` too until round 1, below), lattice functions and `library(lattice)`, `plot_ly`/`ggplotly`; ggplot2: `qplot(`, and `ggplot2`/`tidyverse` among the package names (`lattice` left that list). Since round 1 the package names are an R signal, not part of the grammar: they say the code is R, not that it draws with ggplot2 (`library(tidyverse)` then base `hist()` was read as ggplot2). Python: a `%pylab`/`%matplotlib` magic, `True`/`False`/`None`, a block opened with a colon, plotly (`import plotly`, `px.`, `go.Figure(`, `.update_layout(`, `.write_image(`), Altair (`import altair`, `alt.Chart(`, `.mark_*(`).
- **Names other systems share.** Of base R's and lattice's plotting functions, seaborn 0.13.2 has `barplot()`, `heatmap()` and `stripplot()`, and pylab and plotly.express have `histogram()`; none of seaborn, pyplot, pylab, plotly.express and pandas.plotting has `pairs`, `curve`, `dotplot`, `barchart` or `cloud` (MEASURED: `hasattr` on the installed modules, round 1). These four do not score R and name base graphics or lattice only once the code is R; the first version scored them as R and named them whatever the language or pick, so a bare seaborn `stripplot()` was "Python / lattice", refused.
- **plotnine.** A `ggplot()` call with plotnine imported (`from`/`import plotnine`) is Python and plotnine, whatever the rest of the code says and whatever the user picked. The other markers are hints, because R can write them too: `aes()` given strings, `theme()` with underscore names, a `.save()` method. With a `ggplot()` call and nothing in the code R's alone (no R signal fired: `library()`, `<-`, `df$col`, …; and no line ends in `+` outside every bracket, how R carries a ggplot chain onto the next line, which Python cannot, so plotnine wraps its chains in parentheses), a hint takes the grammar's words out of R's score: Python's own signals then decide (`se=False` makes it Python and plotnine), and with none the code cannot be placed. Since round 2; until then a hint alone made the code Python and plotnine, so R ggplot2 with a string in `aes()` whose chain sits inside `print()`, `ggsave()` or a loop's braces, where no line ends in `+` outside every bracket, was refused (R2-01). With a line ending in `+` outside brackets, or an R signal, a hint does not count and the code scores as before. A pick of R checks hinted code as ggplot2; a `ggplot()` call in code picked as Python is plotnine. A call, not just the grammar's words: `.save()` is PIL's too, and a seaborn FacetGrid may be called `facet_grid` (the first version used the words; section 8). A module prefix is allowed (`p9.ggplot(` after `import plotnine as p9`; the second version missed it, found in the self-review before the frozen copy, with its row and mutant). Until round 1 any hint decided, ahead of the scores and of a pick of R, so R's `aes(x = "")` (a pie) and `aes(colour = "Observed")` (a legend label) were refused as plotnine (section 9); until round 2 a hint still decided when nothing R's alone fired.
- **A plotting system beside the language.** `describePlotCode(code, picked?)` returns `{ language, system, assumed }`: plotnine as above; for R, a grammar call means ggplot2 (a package name alone does not); for Python, pyplot, Axes or seaborn mean matplotlib; then lattice, plotly, Altair and base graphics by their own calls (whatever the pick: picking R on a base plot, or on plotnine imported, does not make it ggplot2), except the four shared names, which count only in R; then `plot()`, `hist()` and the like are base graphics in R, and pandas' plot methods and pylab's bare calls matplotlib in Python (after plotly, so `px.scatter()` stays plotly); otherwise the language's own system, marked `assumed`. The system follows from the code and the language. `plot(x, y)` alone has no language. `detectLanguage` is its language; `languageSignals` returns the scores and every signal that fired (for the harness). `SUPPORTED_SYSTEMS` is `ggplot2` and `matplotlib`.
