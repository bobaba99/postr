**Source:** `docs/stress-test/PLAN.md`, the claims audit's HIGH "the paid PowerPoint export leaves out charts made in the Figure tab, with no warning" (the owner kept chart blocks on 2026-10-07, so it blocks the MVP), fix 13c's queued "Charts are not in the PPTX export", record 30's queued "Placeholders print" (its INFO ui-copied and ui-font) and record 29's R1-02 (Save PDF prints the editor's hints in empty authors, image and references blocks); the product reference is the MVP design doc, `docs/launch/mvp-editor/bounded-designs.md` (§3.10 Export, §3.1 rule 6: prompts never print) · **Branch:** `fix/exports-charts`, off main `5a0a587` · **State:** implemented; review round 1 (code review) answered: 4 findings corrected (2 MEDIUM, 2 LOW), 2 INFO noted, 1 sibling found while correcting and queued; review round 2 (a new angle) answered: 1 MEDIUM corrected (R2-F1: Preview opened while the export waited wrote a paid file with no charts), 2 LOW doc claims corrected, 3 INFO noted, 1 sibling hypothesis queued; round 3 due (section 9).

## 1. Symptom

A researcher who pays for the PowerPoint export makes a chart in Postr (Insert › Chart, or Figure › Make a figure), exports, and opens the file: the chart is not there, nor its caption, and nothing said so. The Export tab told them ("Charts made in Postr are not included."), in small print under the button.

Whoever saves the free PDF of a poster with a block still empty finds the editor's own prompts printed on it: "+ Upload figure · click to browse · drag to move" in an empty figure, "Add references in Refs tab →" in an empty references block (in the editor's interface font, DM Sans, which the print window does not load), "Add authors in sidebar →", "+ Logo", and a chart's "Something went wrong rendering this chart." with a "Send Feedback" button.

## 6. Root cause

**A — the PowerPoint file has no charts.** `export/pptx/writer.ts` writes each block from the poster's data, `switch (b.type)` over title, authors, heading, text, image, logo, table and references; a `chart` block matches no case and is skipped, with no warning (INSPECTED, and MEASURED in section 4). A chart exists as a drawing only in the editor: `charts/ChartBlock.tsx` draws its `ChartSpec` with Observable Plot into an svg, at the box the block is laid out in (fix 13c), and the writer, built as pure `PosterDoc → bytes`, has no drawing to place. The free PDF has the charts because the one print function copies the editor's sheet, svgs included (record 30).

**B — the editor's hints print.** The one print function copies `#poster-canvas` and `stripEditorChrome` removes what carries one of four markers (record 30, R2-F1's `data-postr-editor-ui` among them). The hints are ordinary elements inside the blocks' content with no marker: `ImageBlock`'s and `LogoBlock`'s empty-state buttons, `AuthorLine`'s two "Add authors in sidebar →" spans, `RefsBlock`'s empty-state div, `ChartBlock`'s loading and failure overlay (INSPECTED). The same class of cause as record 30's R2-F1 (the table's hover controls): editor UI inside a block's content, unmarked. The thumbnail copies the sheet through the same function and carried them too (TESTED).

**C — "References" over an empty list in the PowerPoint file.** `addReferences` wrote its title run before its entries, whatever their number (INSPECTED). The editor shows only its hint there; with B fixed the PDF shows nothing.

**What these do not explain:** an image block's caption placed by the writer's own one-line layout, which a long caption runs past (section 10: a sibling of A's "the writer guesses what the editor lays out", measured, not changed); an empty figure's "Figure N." label (it is the caption's number, not a hint: section 10); the out-of-bounds text's white colour copied into the print (on PLAN's list from fix 13c; editor state in the copy, but not a hint).

**Why this shape.** The picture is read off the editor's sheet rather than drawn again from the spec because the editor's drawing is the thing to reproduce: the chart is laid out for the box the frame leaves (fix 13c), with its caption's height taken from the wrapped caption, and re-deriving that from the data would re-implement the editor's layout (a top caption's lines). Reading the sheet is plain: the svg as drawn, its host's laid-out size (computed width and height, before any transform; its viewBox, the size it was drawn for, where the page gives none, as in jsdom) centred where it is drawn (a turned box's bounding rectangle has the box's centre), the caption and note marked `data-postr-caption` and `data-postr-note` in `CaptionWrapper` and read the same way. It is the one place the writer reads the page, injected (`drawChart`) with this default as the svg rasterizer is (`rasterizeSvg.ts`), so the writer stays `PosterDoc → bytes` for tests. The export runs from the Export tab, inside the editor, where every chart is drawn (or, since review round 1, waited for until it is, and since round 2 until the poster is shown: rule 6), and reads the page once, before the writer's first await (rule 10).

The hints take the existing marker instead of a new one: it already means "a block's own editing UI inside its content" (record 30), `stripEditorChrome` drops it for the print and the thumbnail alike, and `print-path-check.mjs`'s reading skips it in the editor, so the editor's sheet and the print document compare as before (the hint is not the user's text).

The writer's shared emitter pieces (the context, sizes, rich-text runs, the caption split and the muted text box) moved unchanged to `export/pptx/shapeKit.ts`, `paragraphsToTextProps` and `normalizeRotation` re-exported from `writer.ts`, so the chart's emitter can use them and `writer.ts` stays under 800 lines (764 before, 622 after; the mutant specs of fixes 27 and 28 that edit it still apply: section 8). `addMutedText` takes an optional turn.

**Out of scope** (recorded): native, editable PowerPoint charts (the owner may ask later: Later, section 10); the LaTeX export (hidden; its re-enable list keeps "it drops Figure-tab charts"); exporting a chart's data; an image block's caption placement in the PowerPoint file (section 10); the Issues row for empty blocks (fix 29's); what an empty figure's "Figure N." label does (an owner question).

## 10. Limits and follow-ups

- **Native, editable PowerPoint charts: Later** (the owner may ask). The picture keeps the chart exactly as drawn; its text cannot be edited in PowerPoint (the caption can). pptxgenjs's `addChart` covers some forms, not every form Postr draws (heatmap, dumbbell, box: UNVERIFIED).
- **PowerPoint, Keynote and Google Slides were not opened** (UNVERIFIED): opening PowerPoint here would take over the owner's desktop. LibreOffice 26.2.3.2, Quick Look and the app's own reader read the files (MEASURED). An owner check is in manual flow §35.
