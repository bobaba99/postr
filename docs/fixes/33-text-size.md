# Record 33 — Text size: one control for the whole poster

**Source:** the MVP editor design, `docs/launch/mvp-editor/bounded-designs.md` §3.7 (owner decision D2: the control in the top bar), as amended by the owner on 2026-10-07 (Auto-Arrange never changes a font size, so it does not press A−; record 28 built it that way and it stays so) · **Branch:** `fix/text-size`, off main `c67a3db` (first built on `1d5addf`; that tree was lost before it was committed and the build was recovered from the author's transcript onto `c67a3db`, section 9) · **Status:** implemented; reproduced first in Chromium, Firefox and WebKit with a new committed instrument (`apps/web/scripts/text-size-check.mjs`), green after the change in all three; 25 of 25 mutants killed, 3 blind spots guarded in the browser; its one review round (a simple feature: the browser, through the user's entry points, on the frozen copy `textsize-frozen-1`) done and corrected (section 9: 6 findings; R1-F1 MEDIUM, a body that is not a size, and R1-F5 LOW, a level that is not a size, one cause, corrected, each reproduced first in the three engines and red-then-green; R1-F2 MEDIUM, a level reset on reopen after A+ from a small body, left to the lead and the owner with the record corrected; R1-F3 and R1-F4 LOW, measured and recorded; R1-F6 INFO); after the correction 32 of 32 mutants killed, 3 blind spots guarded in the browser; the correction is for the next lead pass, frozen copy `textsize-frozen-2`.

Evidence labels as in `docs/fixes/README.md`: MEASURED (a number from a re-runnable command), TESTED (a test that fails without the change), INSPECTED (read, nothing ran), UNVERIFIED.

## 1. Symptom

A researcher wants all the text on the poster one step larger (the poster is going on a big board) or smaller (the text runs past the bottom). PowerPoint has Home › Increase / Decrease Font Size for that. Postr's editor had no such control: the top bar held Undo, Redo and Save PDF. The only way was Style › Typography, four size fields (title, heading, authors, body), each typed by hand, each its own undo step, the new value worked out by the researcher; the fields show whole points, so the ratios drift and a step up and back down by the same route does not return to where it started. The Edit tab told a selected text block's user to "Change the size in the Style tab, under Typography."

## 3. Method

`apps/web/scripts/text-size-check.mjs` (new), with `lib/textSizeRead.mjs` (what is read: each level's computed font-size on a sheet, the control as a user meets it, the top bar's boxes, the store's sizes as a passive read, a PowerPoint file's run sizes), `lib/textSizeKit.mjs` (the user's actions and the rule's expected values), `lib/textSizeLadder.mjs` (the ladder scenario), `lib/textSizeScenarios.mjs` (the others) and `lib/textSizePosters.mjs` (posters), on `lib/editorHarness.mjs` (the app's Vite server, the backend faked at the network, a term holder), `lib/printPathPosters.mjs` (the five templates and the welcome poster, reused), `lib/keepWorkKit.mjs` (`openPrintWindow` from the top bar, `downloadPptx`), `lib/undoKit.mjs` (Tab to a button, the caret) and `lib/arrangeRead.mjs` / `lib/simplifyKit.mjs` (overlaps, Issues rows). A sibling of `print-path-check.mjs` or `pptx-export-check.mjs` would not fit: those compare a document with the editor at one moment; this one presses the top bar many times and reads the store between presses. It reuses their posters and readers instead.

Every scenario enters as a user does: the top bar's buttons clicked with Playwright's pointer, or reached with Tab / Shift+Tab and pressed with Enter and Space; the top bar's Undo and Redo; the sidebar's tabs; the Style tab's field typed into; typing at the caret; the top bar's Save PDF; Export › PowerPoint. Expected sizes come from the rule table applied to the sizes the poster is drawn at before the first press (read from the sheet), not from the app's code. The claims, information readings and blind spots are in the harness's header. Re-run (from `apps/web`):


After review round 1 the reviewer's probe was folded in where it found a defect or measured a limit (`lib/textSizeEdgeScenarios.mjs`, new; posters `EDGE_POSTERS` in `lib/textSizePosters.mjs`, kept off the ladder): the Style tab's Body field cleared with its own keys (select all, Backspace), then A−, A+ and the top bar's Undo (NOSIZE, NOSIZEUP, NOSIZEU); a body stored as null, a string or a negative number, then A+ (ODDCTL, ODDUP); a title stored as null, then A+ and A− twice (ODDLEVEL); and as information one A+ from a body typed at 12 pt, saved and reloaded (RELOAD12), the two round trips the anchor does not keep exact (RTRELOAD, RTSTYLE), and the top bar at 390 and 384 px. What the instrument does not cover: what is painted (a size is the computed font-size of each block's text); charts, captions, tables and the references block, which follow the body by their own rules (captions read as information); the native tooltip of a title (the attribute is read); a reload inside a round trip; the production build (the store reads need the dev server).

## 6. Root cause

- **No bulk control** (H1–H3): no block stores its own size (`packages/shared/src/types/poster.ts` `Styles`: four levels), so a level's size already reaches every block of that level, but nothing changed all four together. The Style tab's fields (`Sidebar.tsx` `StyleEditor`) show `Math.round(unitsToPt(size))` and store `ptToUnits(typed)`, so a user who scales by hand types rounded values: the ratios drift, and a size like the default title's 100.8 pt (14 units) comes back as 101. Fix 12 removed the selection toolbar's A+ / A− because they never reached the poster (the sanitizer drops a font-size); nothing replaced them.
- **Why the design's "not rounded, so it returns exactly" needs more** (H4): a press multiplies by new ÷ old body, for example 40 ÷ 36. In floating point (x · 40/36) · 36/40 is often not x, off in the last digits (the naive formula misses on 4526 of 4549 swept walks, by at most 6.1e-16 of a size, a few units in the last place: invisible, but not `===`; section 8, MEASURED). And no formula on the four sizes alone can always undo a press: A+ scales a size up by less than 2 while the spacing of representable numbers can double (a title of 7.9 units scaled to 8.8 crosses 8), so two different starting sizes can land on one; A− then cannot know which to return to (a counting argument, INSPECTED). The state must carry more than the four sizes; the anchor of section 7 is that state, held in the tab.
- **Siblings looked for:** (a) the Edit tab's level note named only the Style tab (fixed, rule 6). (b) A figure's caption and note follow the body by an older rule, `Math.round(styles.body.size * 0.85)` in poster units (`blocks.tsx` `CaptionWrapper`; the PowerPoint writer the same, `export/pptx/shapeKit.ts`), so they move in 7.2 pt jumps: at a body of 28 / 32 / 36 / 40 / 44 / 48 pt a caption is 21.6 / 28.8 / 28.8 / 36.0 / 36.0 / 43.2 pt (MEASURED, the ladder's `captions`, every template and the welcome poster); A+ from 32 to 36 leaves captions alone and 36 to 40 raises them 25 %. Older than this record, the same in the print document and the PowerPoint file; changing it would resize every existing poster's captions. Later list. (c) ⌘⇧> / ⌘⇧< were already unbound (H5). (d) Auto-Arrange changes no size (record 28's G1; here ARRANGE after A+ to 48 pt, clean). (e) The print document and the PowerPoint file read the same style levels (`export/printDocument.ts` copies the sheet; `export/pptx/writer.ts` `styleOptions` reads `styles.*.size`), so they follow without a change (PRINT, PPTX).
- **Sibling f, found while building and left open (MEASURED, RELOAD, Chromium, Firefox and WebKit):** when the editor page opens a poster it replaces any level above a ceiling (`pages/Editor.tsx` `normalizeStaleStyles`: title 30, heading 14, authors and body 10 units, i.e. 216, 100.8 and 72 pt) with today's default, taking it for an old document's broken default (title 60 / heading 28 / body 18 units). A level a user set large and then raised with A+ can pass a ceiling: a title of 170 pt and a heading of 80 pt at a 36 pt body, A+ to 48 pt, become 226.67 and 106.67 pt, are saved, and on the next open read 100.8 and 57.6 pt. The body never passes its ceiling (48 pt is 6.67 units), and at the default ratios no level does (the title reaches 134.4 pt, the welcome poster's 194.7 pt). A level passes when its ratio to the body after the press is above the ceiling's: at a body of 48 pt a title above 4.5 ×, a heading above 2.1 × and authors above 1.5 × the body; at 28 pt 7.7 ×, 3.6 × and 2.57 × (INSPECTED, arithmetic on the ceilings). The ordinary way there, found by review round 1 (R1-F2, section 9): a body typed small in the Style tab, whose field takes 12 pt as its own minimum, leaves the other levels where they are, so their ratios grow; one A+ to 28 pt then takes the title from 100.8 to 235.2 pt, the heading from 57.6 to 134.4 and the authors from 36 to 84, and the next open reads 100.8, 57.6 and 36 (MEASURED, RELOAD12, three engines). With the default level sizes, a body typed below 16 pt loses the heading this way, below 14 pt the authors and below 13.07 pt the title (INSPECTED, arithmetic). The path is older than this record: the Style tab's heading field takes up to 200 pt, and 110 pt typed there is reset to 57.6 on reload with no A± at all. Not changed here: the ceilings are how the editor recognises older documents, and changing what it resets on load is a decision about older posters outside this record's brief (PLAN.md's Later list, for the lead and the owner; a bounded design would recognise the old defaults by their own values, or keep A+ below the ceilings).
- **Not explained by this, and not changed:** the overlaps and blocks past the sheet that A+ to 48 pt makes on some posters (section 8, information): the poster's blocks keep their place and size rules (text blocks grow with their text, as the size field already makes them), as the brief says; Issues lists them.

## 7. The change

**The rule module** (`apps/web/src/poster/textSize.ts`, new; its header is the rule table): `BODY_SIZES_PT` 28 · 32 · 36 · 40 · 44 · 48; `nextBodyPt(pt, step)` the next size above or below (a body between two sizes or outside them goes to the next one; null at a bound, sizes within 1e-6 pt the same); `stepTextSize(styles, step)` the styles after one press, only the four sizes changed (weight, italic, line height, colours and any other key kept); a body that is not a size is below every size (rows 7 and 8, added after review round 1, below). The levels at a body size p are computed from an **anchor**, the sizes before the first press of a run: each level is `anchor level ÷ anchor body × p`, and at the anchor's own body the anchor itself. So the sizes at a body are a function of the anchor and the body alone, and returning to a size returns its sizes exactly, after any sequence of presses (and Undo / Redo of them). A press starts a new anchor when the poster's sizes are not the anchor's at its body: a size typed in the Style tab (rule 5: its new ratio is kept from then on), another poster, or a reload (the anchor is held in the tab). This is the only state the feature adds.

**The control** (`apps/web/src/poster/TextSizeControl.tsx`, new): a group `role="group" aria-label="Text size"` `data-postr-text-size` in the top bar, 8 px after the History group (`EditorTopBar.tsx`; the History group's width is now derived from its own sizes, `HistoryButtons.tsx` `HISTORY_GROUP_WIDTH`, and both groups share `topBarGroup`): A− (`aria-label` "Decrease text size"), the label "Body {n} pt" (the body in whole pt, `aria-live="polite"`), A+ ("Increase text size"). Titles say where a press takes the body ("Increase text size (body to 40 pt)") or, at a bound, why not ("Largest text size: the body is 48 pt or more", "Smallest text size: the body is 28 pt or less"); a button at a bound is greyed and `aria-disabled`, kept focusable so a keyboard user who stepped to the end keeps their place, and a press there does nothing. A press writes the four levels in one `patchDoc` (one undo step in fix 12's one history). A mouse press cancels mousedown, so the caret stays in the text and the next letter lands after the last; a press from the keyboard keeps the focus on the button. Keys pressed on A− / A+ do not reach the selection: `editorHistory.ts` `onHistoryButtons` also answers for `[data-postr-text-size]` (a line added before fix 12's, which is unchanged).

**After review round 1 (R1-F1 and R1-F5, section 9): a size that is not a size.** The first build guarded one case in one place: a press on a body of 0 changed nothing, while the control worked out its title and enabled state on its own, so a cleared Style-tab field left A+ enabled, promising 28 pt, and doing nothing. Now one predicate, `isSize` (a positive, finite number of units), and one answer, `bodyTarget(stored body, step)`, serve the press, the label, both titles and the disabled state. Two rows join the rule table in `textSize.ts`'s header. **Row 7:** a body that is not a size (0, which the Style tab's Body field stores when it is cleared, or a negative number, null or a string, which only a stored poster holds) is below every size (rule 2): A+ sets the body to 28 pt and leaves title, heading and authors as they are (there is no ratio to keep; dividing by the body would write Infinity or NaN into the poster), A− does nothing. The label shows no number, "Body – pt" (0 draws no text; null, a string or a negative number draw at the size the page inherits, which the control cannot name); A+'s title is "Increase text size (body to 28 pt)", A−'s "No body size: A+ sets the body to 28 pt". The control shows whenever a poster is open (it was hidden on a body of null). **Row 8:** another level that is not a size (a title of null) is left as it is by every press, instead of being multiplied into 0.

**The note** (`Sidebar.tsx` `TextLevelNote`, rule 6): "Type on the poster to edit this block. A− / A+ in the top bar change the size of every text level together (title, headings, authors and body); the Style tab, under Typography, changes one level." True as written: the four levels change, captions, tables and references follow the body by their own rules, chart text does not change (it has its own sizes, `charts/`), so the sentence names levels, not "all text".

**Not changed:** Auto-Arrange (record 28), the Style tab's four size fields (rule 5), the print document and the PowerPoint writer (they read the levels), the About page's "36 pt body text" (still the default), the onboarding tour and the landing copy (neither describes text sizing). The design doc §3.7 gains a note on what was built and the two rows that do not hold (Auto-Arrange's A−, the folded fields).

**One cause for R1-F1 and R1-F5, looked for before designing the fix.** The rule module and the control assumed that every stored level size is a positive, finite number, and nothing makes it one. The Style tab's size field stores `ptToUnits(+value)`, so a cleared field stores 0, and so does a lone minus sign (React then shows 0; "-36" is stored as 36, the minus dropped; "5" as 5 pt, below the field's own minimum of 12: MEASURED, a probe typing into the Body field, Chromium, not committed: `<scratch>/probes/minus.mjs`). A stored poster can hold null (a NaN written as JSON), a string or a negative number, and the editor page's load-time repair keeps them (`normalizeStaleStyles` replaces only a missing level or one above its ceiling; INSPECTED, and the stored values reached the store in the probe's and the instrument's runs). The first build guarded one case in one place (the press, for a body of 0) while the control worked out its title and its disabled state on its own, from `nextBodyPt(unitsToPt(size))`, so the two disagreed; and `sizesAt` multiplied every level, a null one included.
