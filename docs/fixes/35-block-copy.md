## 1. Symptom

A researcher selects the figure and its heading she has just finished and presses ⌘C, then ⌘V, to lay out a second figure the same way: nothing is copied, and ⌘V drops a text block of whatever text she copied last. ⌘X does nothing. She copies a block to put it on her other poster: the same. She duplicates a figure with ⌘D, replaces the original's picture with a new version of the plot, and after a reload the duplicate shows the new plot too. She replaces a figure, changes her mind and presses ⌘Z: the block takes its old size, but shows the new picture squeezed into it.

## 6. Root cause

- **C (H1, H2): the feature did not exist.** No listener wrote blocks to the clipboard, and record 34's paste reader had a marked place, not a check, for its order 1 (`canvasPaste.ts` `readCanvasPaste`, base), so a payload's HTML was read as text (order 4).
- **D (H3, H4): files were named after their block and overwritten.** `uploadPosterImage` wrote `{user}/{poster}/{block}.{ext}` with `upsert: true` (base `posterImages.ts:46, 54`; `uploadBase64Image` the same, `:128, 134`), so one path held a block's picture across every upload of the same type. Everything that kept a path pointing at the earlier picture saw the new one: ⌘D's clone (it copies `imageSrc` with the rest of the block, base `PosterEditor.tsx:1786-1791` `duplicateBlock`, `...src`), the undo step before a Replace, and (INSPECTED, not measured) a saved version restored after a same-type Replace, and a poster made with the dashboard's Duplicate (`data/posters.ts` `duplicatePoster` copies `data` as it is: its blocks point at the original poster's files, which a Replace in the original overwrote).
- **Siblings looked for (one cause, D):** record 34 §10's three items are this cause: the undo after a same-type replace (H4, measured here), two files put into one image block in quick succession (both wrote `{block}.{ext}`; with the same extension the block showed the later file only if its upload landed last), and Preview, the print window or an export drawing a cached old file after a same-type Replace (`resolveStorageUrl` keeps a signed address per path 50 minutes; a new path signs anew). `uploadBase64Image` (the migration of a poster's data URLs to storage, `pages/Editor.tsx` `migrateBase64ToStorage`) wrote `{block}.{ext}` too. Import (`pdfImport.ts`, `pptxImport.ts`, `postrFile.ts`) goes through `uploadPosterImage`. The thumbnail (`{user}/{poster}/thumbnail.jpg`) is overwritten by design and no block points at it. The logo's picker stores a data URL (an upload; `pages/Editor.tsx` `migrateBase64ToStorage` turns it into a poster-assets file, `{block}-{random}.{ext}`, when the poster is next opened: the reviewer's MEASURED in review round 1, INSPECTED here), a preset's address (`logoPresets.ts` `resolvePresetLogo`: Wikimedia or a site's icon) or a My Logos signed address (section 10).
