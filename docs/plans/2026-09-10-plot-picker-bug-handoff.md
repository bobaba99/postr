### 2.1 Parsing (parseData / parseExcel)

**B1. Blank top-left cell in a pasted cross-tab shifts every header one column left** · high · wrong-result
`parseData.ts:133` feeds `cleaned.trim()` to Papa.parse; `String.prototype.trim` removes the leading TAB that represents the empty corner cell, so the header row parses one field short. `tabulate()` (`parseData.ts:80`) pads short rows on the right (`:92-96`) and names the extra column `Column 3` (`:100-102`), so the row-label column is titled "Control" and the real Control values sit under "Treatment". Comma-delimited input parses correctly, proving the defect is specific to a leading tab. Excel/Sheets ⌘C of any cross-tab with blank A1 produces exactly this TSV, and the misassignment is silent.
Repro: `parseDelimited('\tControl\tTreatment\nMean\t5\t6\nSD\t1\t2')` → header `['Control','Treatment','Column 3']`.
Fix: keep `cleaned.trim().length === 0` for the emptiness check only (`:131`); pass Papa a value that strips line breaks but not cell whitespace (`cleaned.replace(/^(?:\r?\n)+/, '').replace(/(?:\r?\n)+$/, '')`). Test the blank-corner and trailing-tab cases.
Finder: static.

**B2. Header row containing any numeric cell is demoted to data** · high · wrong-result
`looksLikeHeader()` at `parseData.ts:72` returns false when ANY first-row cell is numeric-looking. `tabulate()` then synthesises `Column N` names (`:100-102`) and keeps row 0 as a data row (`:104`), so `inferOne()` reads the header literals as observations — a year header of 2019 is averaged with 1.2-scale values. Wide tables with year/timepoint/dose headers (the default Excel export shape) and Excel-native numeric headers via `tabulate()` all hit this. The existing test pins only the all-numeric first row.
Repro: `parseDelimited('Country,2019,2020,2021\nA,1.2,1.4,1.5\nB,2.1,2.0,2.3')` → header `['Column 1',…]`, `rows[0] === ['Country','2019','2020','2021']`; in the page the ladder asks "What did you measure? Column 2 / Column 3 / Column 4".
Fix: treat row 0 as a header unless it is ENTIRELY numeric-looking (`first.every(isNumericLooking)`), optionally corroborated by a type-profile check (text cell present AND body ≥90% numeric under the numeric header cells). Tests for `'Group\t1\t2\t3'`, `'Country,2019,…'` and native-number year headers.
Finders: static, fuzz.

**B3. Duplicate column headers are not de-duplicated, so encodings, series, panels and lookups silently collide** · medium · wrong-result
`tabulate()` keeps duplicate names verbatim (`parseData.ts:100-104`); everything downstream is keyed by name: `plotOptions.ts:65-76` `toObjects()` writes `obj[col.name]` so the later column overwrites the earlier, `recommend.ts:174` `byName()` returns the first match, and `buildChartSpec` emits the same name for x/series or y/series. A `Group,Group,Score` table renders bar-grouped with x, fx and series all bound to the SECOND Group column (first column absent from the figure); `Time,Group,Group` uses the value column as the series; `Score,Score,Group` yields panels `['Score','Score']`; codegen emits duplicate dict keys. The declared-variables path already de-duplicates (`declaredVariables.ts:151` `resolveNames`), so paste is inconsistent with it.
Repro: `parseDelimited('Group,Group,Score\nA,X,1.2\nB,Y,2.1\nA,Y,3.3\nB,X,4.0')` → top rec encoding `{x:'Group', series:'Group', y:'Score'}`.
Fix: de-duplicate in `tabulate()` with the `resolveNames` scheme (`Group`, `Group 2`, `Group 3`) — ideally extract it to a shared helper. Tests: parseData dedupe; buildSpec/recommend on the two-Group table; unique codegen keys.
Finders: static, fuzz.

**B4. A single pasted column of numbers is rejected as prose, so the histogram path is unreachable by paste** · medium · ux
`parseData.ts:144-145` returns `no-delimiter` for every one-column grid before `tabulate()` runs; `DataStep.tsx:69-70` maps that to "That looks like prose, not a table". The same column through `parseTableBlock` (poster-table path) or a one-column .xlsx parses fine and `recommendFigures` yields histogram/box, so only the paste and CSV-upload entries refuse it (CSV upload also routes through `parseDelimited`, `DataStep.tsx:131-141`).
Repro: `parseDelimited('RT\n320\n410\n385\n402')` → `{ok:false, reason:'no-delimiter'}`.
Fix: only treat a one-column grid as prose when its body is not numeric (`isSingleNumericColumn`: ≥90% of rows after the first satisfy `isNumericLooking`). Keep the prose rejection; keep DataStep's single-line guard.
Finder: static.

### 2.2 Column inference (inferColumns / designShape)

**B5. Missing-value tokens (NA, N/A, NaN, null, '-', '.') are treated as text, flipping numeric columns to 'category'** · critical · wrong-result
`inferColumns.ts:52` `rawToText()` only maps empty strings (and null/undefined) to null; every literal missing marker survives as a text value. `inferOne()` at `:151-152` requires `numericish/nonNull >= KIND_THRESHOLD` (0.9, `:98`), so any column with >10% markers falls to `finish('category')` at `:159`. `designShape.classifyColumns` then sees no continuous column → 0 DVs → summary-table dead end ("Every column is a label or a grouping factor…"), or — when an integer column such as Dose survives — promotes the independent variable as the sole outcome and offers the measurement values as grouping chips / legend entries. Blank cells alone work, so this is specifically token handling; R/SPSS/Excel exports carry these markers routinely. This is also the sole trigger of B24 (⚠ glyph).
Repro: paste `group,mass,temp` with one NA per column (7 rows) → step 2 offers mass/temp as grouping chips, preview shows no figure. Unit: `parseDelimited('Group,Score\nA,4.2\nB,NA\nC,NaN\nD,null\nE,\nF,-\nG,5.1\nH,6.3')` → `columns[1].kind === 'category'`, zero recommendations. 3 NA in 20 rows (15%) flips the same way; 1 in 20 (5%, the existing test) does not.
Fix: in `rawToText` add `MISSING = /^(na|n\/a|nan|null|none|nil|-|--|—|\.|#n\/a|#null!|missing)$/i` → return null before any kind test. Tests: 20% NA → kind number with nulls; mixed markers → number; `group,mass,temp` still yields bar/box; `s4_units.csv` detects Body mass / Δ temperature as outcomes.
Finders: desktop, fuzz.

**B6. MONTH_NAME regex matches any word starting with a month prefix, turning ordinary category columns into a time axis** · high · wrong-result
`inferColumns.ts:45-46` `MONTH_NAME = /^(jan|feb|…|dec)[a-z]*(…)?$/i` — the `[a-z]*` accepts Novel, Augmented, Marketing, Decreased, Junior, Maybe, Marbofloxacin, Novobiocin, Septrin, Decitabine…; `hasDateShape()` (`:184-186`) only requires ≥2 distinct values, so two such labels at ≥90% coverage win the date rule at `:147-148`. `resolveRoles` then picks the column as time and a two-group comparison is ranked line/area/bar-over-time — and because `new Date('Novel')` is invalid the recommended line renders blank (same mechanism as B20).
Repro: `inferTable({header:['Condition','Score'],rows:[['Novel','5'],['Augmented','6'],['Novel','7'],['Augmented','8']]})` → `Condition.kind === 'date'`, shape trend, top form line. Control `Novel/Familiar` stays category.
Fix: anchor full and abbreviated month names only: `/^(jan(uary)?|feb(ruary)?|mar(ch)?|apr(il)?|may|june?|july?|aug(ust)?|sep(t(ember)?)?|oct(ober)?|nov(ember)?|dec(ember)?)\.?([ '-]?\d{1,4})?$/i`. Tests: Novel/Augmented and the drug names stay category; 'Mar 2024', 'March', 'Sept' still date.
Finder: static.

**B7. ID_NAME prefix match turns 'Number of …', 'Case …', 'Sample …' measure columns into identifiers** · high · wrong-result
`designShape.ts:132-133` `ID_NAME` is anchored at `^` with loose tokens (no|num|number|case|sample|name|…); `classifyType()` tests it at `:237` BEFORE any outcome check whenever the column is nearly unique (`:235`, distinct/filled ≥ 0.9) — which a one-row-per-group count column always is. Result: identifier → dropped from DVs → `decideTreatment` summary-table (`:321`) → `isUnchartable` (`:468`) → zero recommendations. The same column with repeated values is correctly 'dependent', and 'Participant ID' correctly stays identifier, so the failure is exactly the one-row-per-group summary table.
Repro: `inferTable({header:['Ward','Number of falls'],rows:[['A','0'],['B','3'],['C','5'],['D','7'],['E','12'],['F','2']]})` → `'Number of falls:identifier'`, summary-table; same for 'Sample size' and 'Case fatality rate'.
Fix: split ID_NAME into (a) unambiguous tokens anywhere `/\b(id|ids|uid|uuid|guid|key|code|email)\b/i` and (b) whole-name identifiers `/^(no|num|number|record|row|index|participant|subject|patient|case|sample|specimen|respondent|student|name)\s*(id|no|#|number)?\.?$/i`; for numeric columns test OUTCOME_NAME (count, number of, rate, size) first. Tests: 'Number of falls', 'Sample size' → dependent; 'Participant ID', bare 'Sample', 'Case no.' → identifier.
Finder: static.

**B8. Any integer measure whose values fall in 1800–2200 is read as a year axis and vanishes from the outcome list** · medium · wrong-result
`inferColumns.ts:174-176` `isYearLike()` returns true for ANY integer column with ≥2 distinct values all in [1800, 2200], no name corroboration. `recommend.ts:132` `measureCandidates()` excludes ordered columns, `designShape.ts:243` maps ordered → 'temporal', and with one factor the design is '0 outcomes × 2 factors' → summary-table → no figure and no way to override. A single value outside the window or any decimal escapes it, so the trigger needs every value to be an integer inside a 400-wide band (slow-task RTs in ms, kcal/day, some weights in g) — real but narrower than the other inference bugs.
Repro: `inferTable({header:['Condition','RT (ms)'],rows:[['A','1850'],['B','1900'],['A','2100'],['B','1950']]})` → `RT.ordered === true`, `measureCandidates → []`, treatment summary-table.
Fix: require corroboration on the bare-range path — `allYearRange && (/(year|yr|cohort|date)/i.test(name) || (distinct === nums.length && isMonotoneRun(nums)))` — and never mark a column ordered when its name matches the outcome vocabulary (export `OUTCOME_NAME` from designShape or move it to a shared vocab module). Tests: 'RT (ms)' 1850–2100 → not ordered; 'Year' 2018–2022 → ordered; unnamed `Column 2` of 2019,2020,2021 → ordered.
Finder: static.

**B9. Binary 0/1 outcome (trial accuracy, survival, response) beside a text factor is declared unchartable** · medium · wrong-result
`designShape.ts:197` `isNumericFactor()` reads any 2–3-level, repeating, gapless integer column anchored at 0/1 as a coded factor unless its name matches `OUTCOME_NAME` (`:140`), which has no binary-outcome vocabulary; `detectDesignShape()` then refuses the reclaim safety net at `:420-423` because `otherFactor` (the text Condition column) is present, so dvCount is 0 → summary-table → `recommend.ts:466-467` suppresses all figures with the note "no measured outcome" — factually wrong for a per-trial Correct column, where mean(Correct) by Condition is exactly the proportion bar the user wants. The gate is deliberate and locked by `designShape.test.ts:168` for a genuine code (`group` 1/2 beside a text `outcome` label); the per-trial binary outcome is collateral. Renaming the column to 'Accuracy' works around it.
Repro: 20-row `Condition (Control/Treatment) / Correct (0/1)` → treatment summary-table, `recommendations.length === 0`; same for 'Survived'.
Fix: (1) extend OUTCOME_NAME with `correct|accurate|success(ful)?|survived|survival|responded|responder|hits?|detected|passed|present|relapse|remission|recall(ed)?|yes`; (2) in the `dvs.length === 0` branch also reclaim when there is exactly one demoted numeric column and every other non-identifier column is non-numeric; optionally caption 'Proportion …' when values are all 0/1. Tests: Condition/Correct and Group/Survived → single-chart; keep the existing group(1/2)/outcome fixture as summary-table.
Finder: static.

**B10. Common numeric formats are not recognised — space thousands, currency prefixes, unicode minus, 'NN,N %'** · medium · wrong-result
`inferColumns.ts:48-50` (DOT_DECIMAL / PLAIN_NUMBER / COMMA_DECIMAL) and `:93-94` `isNumericText()` accept only `[-+]digits[.,]digits[eE]…%` — no whitespace class, no currency glyph, no U+2212, and `%` must be adjacent. `parseNumericText()` (`:79-82`) DOES strip U+0020/U+00A0/U+202F with a comment naming them as European thousands separators, and `parseData.ts:45` NUMERIC_LOOKING admits spaces for header detection, so the gate and the parser disagree (a half-implemented feature). In every case the column becomes 'category', is offered as a grouping factor, and the table has "no measured outcome"; the user cannot recover in the ladder because `measureCandidates` only offers kind number.
Repro: `'Site,Cost\nA,1 234\nB,2 345\nC,3 456'`, `'Item,Cost\nA,$1234.50\nB,$99.00\nC,€45.10'`, `'Group,Delta\nA,+1.5\nB,−2.5\nC,-3.5'` (U+2212), `'Gruppe;Anteil\nA;12,5 %\nB;30,0 %'` → all kind category, zero recommendations; `'12,5%'` without the space works.
Fix: add `normaliseNumericText()` (map leading `−`/`–` to `-`, strip one leading/trailing currency glyph `[$€£¥]`, remove spaces between digits, collapse `\s*%$` to `%`) called at the top of both `isNumericText` and `parseNumericText` (and `decideDecimalStyle`), set `percent` from the normalised form, mirror in `NUMERIC_LOOKING`. Tests for each shape plus a recommend test that space-thousands Cost yields a bar.
Finders: static, fuzz.

### 2.4 Chart build & render (buildSpec / plotOptions / renderChart / download)
